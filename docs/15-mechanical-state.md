# 15 机械状态捕获：把"靠模型自愿"的记账改成"harness 强制"（v0.7.0）

## 一条贯穿性诊断

这个 harness 已经成熟（三预算、缓存友好的板在末尾、实时 jsonl、撞顶/错误连击检测、被杀后重建），但有一个根因性缺陷——之前反复撞到的几个坑，是它的不同投影：

> **凡是 harness 可靠性依赖的状态，都被托付给"模型自愿调用工具"去维护——而模型在高压下不可靠。**

- `update_memory` 靠模型主动写 → 高压下忘记写（实测失败任务 40 轮仅 1 次更新）；
- `task_done` 靠模型自报完成 → 文件没写就声称完成；
- 环境副作用 → **根本没人记**（db-wal：模型亲手删了 WAL 却不自知）。

三件事是同一个错误：把系统的记账外包给模型的善意。修复方向统一——**把 harness 需要的事实，从"模型动作"改成"harness 自动捕获"**。v0.7.0 落了三个 P0。

## P0a：读取每题真实超时，对齐整套收尾机器

**病根**：整套优雅收尾（wall_clock_warn/stop、salvage、no_think）都建立在 `task_timeout_sec` 是真值之上。但 harbor 只把每题超时传给内置 ORACLE，不传自定义 agent——我们一直吃 1800 默认。喂假值的后果不是少一个字段，是**整套收尾系统失效**：harbor 在收尾逻辑触发前就硬杀，永远拿不到 task_done，只拿到尸体（db-wal 就是被 900s 杀在第 40 轮，交付物没写）。

**预检揭示的规模**：全 89 题里 **48 道真超时仅 900s**（收尾从未在这些题正常触发），另 17 道 >1800（被我们默认值腰斩，train-fasttext 真 3600s）。约 65/89 题此前都在错误截止线下跑。

**修复**：运行时从 `~/.cache/harbor/tasks/**/<task>/task.toml` 解析 `[agent].timeout_sec × multiplier`，`packages/` 布局优先消歧；读不到 loud 退默认。配套 `preflight_timeouts.py`：正式 -k5 前对全量任务校验，有解析不出就中止——把"fail loud"落在预检而非单 trial（后者会白丢一题分）。

## P0b：启动快照 + 逐命令 state-diff 客观账本

**为什么不能用"危险动词清单"**：杀死 db-wal 的命令是 `sqlite3 main.db "SELECT..."`——一条**查询**，任何危险词清单都不命中，却触发了 SQLite 自动 checkpoint 删掉 WAL。**按命令长相猜危险，必漏。** 正解是不猜命令、直接量环境。

两个机械动作，都不判断"危不危险"：

1. **启动快照**：开工前 `cp --reflink=auto -a <工作区> /tmp/_agent_orig_snapshot`（COW，近零成本；不支持则退硬链接 `cp -al`）。关键：sqlite 删 WAL 是 `unlink`，只要快照里还有一份（哪怕硬链接），那个 inode 的数据就不释放——**原始输入即便被删，数据仍活在备份里，可拷回**。db-wal 从"不可救的尸体"变成"可恢复"，全靠启动时这一条 cp。
2. **逐命令差分**：每条改动型命令后 `find <工作区> -printf '%P\t%s\t%T@'` 拍一张文件清单，与上一张比对，把"谁出现/消失/变化"记成客观条目；消失的若是**启动时就有的原始输入**，标为 danger 永久保留，并附上从备份恢复的命令。

**与记忆板分开**：板是模型的主观笔记（可丢），账本是 harness 的客观事实（不丢），各自注入上下文。**成本上限**：工作区文件数 >5000 就整体禁用（重数据任务不拖慢）；任何步骤失败只禁用+记日志，绝不拖垮 agent。

确定性测试（LocalExecutor 模拟 db-wal）：删除被记为 danger、备份保住 WAL、可恢复——全通过。

## P0c：task_done 机械校验

**模型自报完成 ≠ 完成。** task_done 触发 harness 侧检查：从交付物文本抽出绝对路径，用 executor 验**存在且非空**，缺失/为空就拒绝 `stop`、把清单塞回历史让模型继续修。

- **必要非充分**：内容对不对是阅卷器的活（隐藏），harness 只能验存在/非空——但光这层就堵掉"自报完成、文件却缺失/为空"的一批 0 分。
- **逃生阀** `MAX_REFUSALS=2`：路径解析可能误判，达上限仍放行，绝不把一个真做完的任务困死（宁可漏放一个错的，不可拦死一个对的）。

## 刻意保留没动的（已经对了）

板在末尾、实时 jsonl、三预算、撞顶降步/换路、被杀 `populate_context_post_run` 绝不抛异常——这些是成熟设计。

## 一句话

把"靠模型自愿"的状态，逐条改成"靠 harness 强制"——超时真值、客观账本、完成校验，是同一个动作的三个落点。
