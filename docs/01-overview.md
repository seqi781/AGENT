# 01 - 总体方案

> 时间：2026-06-10（项目启动）

## 目标

构建一个能跑 **terminal-bench** 的终端智能体（agent）。terminal-bench 是评测"AI 能否像人一样使用 Linux 终端干活"的基准测试：每个任务在一个 Docker 容器里进行（比如"修复这个启动报错的服务"、"编译这个项目"、"破解这个加密文件"），agent 通过执行命令完成任务，最后由预设的测试脚本（pytest）判分。

## 什么是 Agent？

本项目语境下的 agent 就是一个**循环**：

```
任务描述 ──> [LLM 思考] ──> 调用工具(执行命令/读写文件) ──> 把结果喂回 LLM ──> 再思考……
                 ↑________________________________________________|
                          直到 LLM 宣告 task_done 或预算耗尽
```

LLM 本身只会生成文字；让它"能动手"的是**工具调用**（function calling）机制：我们告诉模型有哪些工具可用（执行命令、读写文件……），模型在回复中输出"我要调用某工具+参数"，我们的代码真正去执行，再把结果作为对话消息还给模型。

## 三层架构

```
┌──────────────────────────────────────────────┐
│  适配层 adapters/        ← 对接不同的评测框架     │
│  （M2 实现 terminal-bench 适配器）              │
├──────────────────────────────────────────────┤
│  Agent 核心 agent/       ← 与任何框架/模型解耦    │
│    core.py    感知-决策-行动循环                 │
│    llm.py     统一 LLM 接口（换模型=改配置）      │
│    tools/     工具系统                          │
│    trajectory.py 轨迹日志（调优的根基）           │
├──────────────────────────────────────────────┤
│  执行后端                 ← 命令真正在哪里跑       │
│    M1: subprocess（非交互式命令）                │
│    M2: tmux（交互式程序、terminal-bench 要求）    │
└──────────────────────────────────────────────┘
```

分层的理由：terminal-bench 只是其中一个目标，核心层不依赖它，以后换别的 benchmark 或本地使用都不用改核心。

## 模型策略（关键决策）

手头只有 OpenRouter 的 API key。OpenRouter 是一个"模型网关"——用统一的 OpenAI 兼容协议转发到各家模型，代价是收 ~5% 手续费、丢失少量厂商专有特性（估算影响 2~5 分），换来的是**一份代码随意切换模型**。

事前调研结论（详见当时的对比分析）：

- **框架质量对分数的影响（10~20+ 分）远大于协议损耗（2~5 分）**，所以先把框架打磨好，厂商原生 API 留到 M4 冲榜时再接。
- **DeepSeek V4**（2026-04 发布）能力已逼近第一梯队（SWE-bench Verified 80.6%，与 Claude Opus 4.6 差 0.2 分），价格便宜 ~20 倍。
- 架构上采用**"统一接口 + 按家适配"**：agent 核心只认一个 `LLMProvider` 接口；OpenAI 兼容协议是事实标准（OpenRouter / DeepSeek 官方 / OpenAI 官方共用一份实现），Anthropic 原生协议是唯一需要单独写的后端（M4 再做）。这也是做模型对比实验的方法学要求——除了模型，其他变量必须完全一致。

### 实测速度（2026-06-10，模拟 agent 单轮：任务+工具→工具调用）

| 模型 | 单轮延迟中位数 | 价格(入/出 每M tok) | 备注 |
|---|---|---|---|
| openai/gpt-5.4 | 1.7s | $2.50 / $15 | 官方直供，极稳；默认未开思考 |
| deepseek/v4-flash | 2.3s | $0.098 / $0.197 | 性价比之王，开发用 |
| openai/gpt-5.3-codex | 2.6s | $1.75 / $14 | |
| deepseek/v4-pro | 4.9s | $0.435 / $0.87 | 第三方云路由，偶有长尾 |

结论：**开发迭代用 V4-Flash**（便宜 25 倍、速度同档），**正式评测用 V4-Pro / GPT-5.4 对比**。OpenRouter 会把 DeepSeek 路由到不同第三方云（延迟波动、偶发坏响应），正式跑分要用 `providers` 配置固定供应商。
