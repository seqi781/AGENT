# 10 - 记忆板：模型自己维护的工作记忆

> 时间：2026-06-10 · 对应代码：`agent/tools/update_memory.py`、`agent/core.py`（board_message、_windowed_history）

推理链修好后，下一个瓶颈是记忆。此前 agent 的"记忆"就是只增不减的对话流水账：跑得久了上下文膨胀到上百万 token（一道题烧掉 1.5M token 的惨案就是这么来的），而真正重要的结论淹没在海量工具输出里。我们需要的是**工作记忆**，不是录像带。

## 设计：问题→已验证的答案

核心思路来自一个观察：探索过程中真正值钱的只有**问题和它验证过的答案**，中间过程毫无保留价值。于是设计成：

- **记忆板（memory board）**：一块由模型自己用 `update_memory` 工具维护的白板，内容是交付物清单、计划（带 todo/done 标记）、已验证的事实（"问题 → 答案（怎么验证的）"）、踩过的坑。
- **每轮全量重写**：调用一次 `update_memory` 就整板替换。这不是偷懒——全量重写天然赋予模型**修正权和删除权**：发现之前记错了，重写时直接改掉，防止"错误记忆不知悔改"。
- **每轮注入最新版**：板不进对话历史，而是每轮上下文末尾以最新版出现一次，历史里永远不会有过期副本。墙钟剩余时间也附在板尾。

配套两条提示纪律：**现实胜过记忆**（工具结果和板冲突时，立刻改板）；**也别迷信板**（围绕某条记忆反复失败时，重新探索验证它，记忆会过期）。

## 历史滑动窗口：没上板的等于没发生

板要起作用，必须有"不上板就丢失"的真实压力。于是上下文每轮重新组装：

```
[system, 任务+首轮协议] + 近期历史窗口(≤150k字符) + 记忆板(最新版)
```

超出窗口的轮次从最老处**整轮丢弃**（assistant 消息和它的工具结果共存亡，避免孤儿消息）。这一刀同时根治了流水账噎死预算的病：那道烧 1.5M token 的题，重跑只用了 112k。

## 验证

20 道全新任务：**12/20 = 0.60**（排除 1 道基础设施故障为 12/19 ≈ 0.63），14 道全程零撞顶，平均每题更新板 2.8 次，预算爆炸基本绝迹。还观察到了设计想要的"悔改"行为：模型发现板上记的路径是错的，重写时主动改正并记下教训。

## 对照业界的四项补强（v0.6.1）

拿 Terminus 2 和 OpenDev 论文的做法对照检查，补了四个洞，全部对症实测病灶：

1. **丢弃兜底骨架**：高压任务下模型会忘记上板（失败题 40 轮只更新 1 次板）。现在整轮丢弃时，机械保留每个工具调用的一行骨架——命令、结果首行、退出码。不依赖模型自觉。
2. **板过期催更**：板连续 8 轮没更新就在板消息里加一行提醒。Terminus 2 强制每轮重写计划，我们用"过期才催"换来更省的 token。
3. **超时诊断**：命令超时的报错现在会提示两个最常见原因（交互式程序在等输入→改用 send_keys；本来就慢→调大 timeout 或 nohup）。
4. **步骤验证证据**：计划步骤标 [done] 必须附一行验证依据，说不出依据就不算完成。
