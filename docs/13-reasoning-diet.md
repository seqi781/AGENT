# 13 推理减负：少想不该想的，别让想过的蒸发（v0.6.6）

## 为什么模型会"想太多"

切换到 DeepSeek 推理模型后我们实测到一个矛盾：日常决策轮它只烧约 47 个推理 token（约 0.6 秒），可难题上单轮能烧 28k–104k 个推理 token，一轮就是 8–20 分钟，有时还撞 max_tokens 上限——正文为零，整轮颗粒无收。

成因有四层：

1. **训练经济学**。强化学习按答对给奖励，思考的 token 成本不由模型承担，于是它学到"不确定时多想总没错"。这也解释了为什么简单轮它收敛很快——失控只发生在难处。
2. **没有收敛判据**。问题太难或本身无解（如"写个比 numpy 快的特征值算法"）时，自我验证循环（想一个 → "wait" → 换一个 → "alternatively"）找不到停下来的答案，膨胀到撞 token 上限为止。
3. **Agent 场景的放大器**：单轮之内模型拿不到新信息，不确定时只能用脑内模拟代替实测——用一万 token 的推理去替代一条 50 毫秒的命令。
4. **思考轮间蒸发**。私有思考（reasoning_content）按协议不回传历史，模型烧五万 token 想清楚的设计只有几百 token 正文留下，下一轮重推一遍。同一笔推理被反复支付——这是"重复推理损耗"的字面来源。

关键换算：推理 token 按输出价计费，10 万 token ≈ 2 美分。**钱不是问题，真正的货币是墙钟时间（900s/1800s 超时杀 trial）和 40 轮的轮次预算。**

## 实测：DeepSeek 唯一有效的控制是个二元开关

逐一探测了所有公开的推理控制参数（/tmp/probe_reasoning.py）：

| 参数 | 结果 |
|---|---|
| `reasoning_effort=low/high` | 静默忽略 |
| `reasoning_effort=minimal` | 400 报错 |
| `thinking.budget_tokens` / `reasoning.max_tokens` / `reasoning.enabled` | 全部忽略 |
| **`extra_body={"thinking":{"type":"disabled"}}`** | **有效：推理 400→0** |

质量对照（probe2）：工具型决策两种模式答案一致；设计型问题上默认模式 15.3 秒撞顶零产出，disabled 模式 2.0 秒给出可用答案。

结论：没有"少想一点"的旋钮，只有开/关。设计必须围绕这个二元开关做。

## v0.6.6 的四条机械修法

教训在前（见 11 章）：被动 prompt 规则管不住训练出来的本能，**所有修法必须是 harness 机械逻辑**，不依赖模型自觉。

### E1 撞顶 → 关推理重试

原 cap 抢救是"注入文字提醒 + 原样重试"，成功率约 2/3，重试还开着推理可能再烧一轮。现在撞顶后的抢救轮直接 `thinking:disabled`：上下文里信息都在，关掉推理逼模型把已有结论落成行动。撞顶轮本来就是废轮，怎么改都不会更差——零风险纯收益。

### E2 收尾抢救期强制快通道

轮数告急（TURNS_WARNING，最后 3 轮）或墙钟告急（剩余 ≤ 2 分钟）时，所有 LLM 调用关闭思考。收尾要的是写盘、清理、task_done 这类机械动作，深思只会把剩余时间烧光。冒烟实测：salvage 轮 2.5s/轮，行为正常（模型还主动 xxd 字节验证）。

### E3 防蒸发阀：截留思考尾巴

`reasoning_content` 拿得到，只是不回传。两个触发点把思考尾巴（结论通常在末尾，截 1600 字符）注回下一轮上下文：

- **撞顶轮**：可见产出为零，被截断的思考是唯一遗产，总是注入；
- **常规轮**：思考 ≥ 12k token 而可见正文 < 400 字符——结论大多锁在即将蒸发的思考里。

注入文案明确要求"直接复用这些结论，别重推；要紧的上板"。

### E4 原地打转标注

run_command 以参数串为键记录 (轮号, 结果哈希)。同一条命令拿到**逐字相同**的结果时，结果尾部机械附加"这条命令第 N 轮跑过，结果一模一样——先改代码/输入/思路再重试"。只标注不拦截（命令可能不幂等，重跑可以有理由）；要求结果也相同才触发，编辑代码后重跑测试这类正当重复不会误伤。

## 刻意不做的事

- **不全局关推理**：难题上的长思考是真实智力来源（成因第 2 层），全关等于把模型降级成非推理模型。掐的是失控和重复，不是思考本身。
- **暂不做方案级"尝试台账"**：方案级标注靠模型自觉（不可靠），命令级台账太噪。E4 的同命令同结果检测是它的精简版，先看效果。

## 验证

- 确定性单测（假 LLM 回放脚本）：E1 开关时序（False→True→False）、E3 两个触发点的注入内容、E4 首次不标注/重复标注——全部通过。
- 真实 API 冒烟：`thinking:disabled` 与 function calling 共存正常，salvage 轮 reasoning_tokens=0。
- 跑分对照（待批准）：重点观察撞顶轮挽回率、平均轮耗时、以及已通过任务是否退步。
